# JS 转 Go：陷阱与惯用法

> **本页关键词**：`:=` 遮蔽、slice append、range 副本、defer LIFO、nil 接口、JSON 导出、循环导入、gofmt、sync.Pool

---

## 一、并发与生命周期

**死锁**：无缓冲 channel 两边都在发、或都在收；`Mutex` 重复加锁；`select` 没有 `default` 且所有 channel 都不就绪。用缓冲、超时、`context` 退出。

**数据竞争**：多 goroutine 写同一变量。JS 单线程少见；Go 用 `-race` 跑测试。修复：Mutex、channel 交所有权、或原子操作。

**goroutine 泄漏**：接收方走了，发送还在阻塞；`range ch` 从不 close。始终让发送方 close，或用 `ctx.Done()` 取消。

**goroutine 里 panic**：没 recover 就整进程退出，不像 Node 一个 Promise rejection 只打日志。对外服务在边界 `defer recover()`。

**channel**：发送方关闭；不要 close 已关闭的；不要向关闭的 channel 发。`nil` channel 会永久阻塞，可用来在 `select` 里禁用某个 case。

## 二、切片、循环、defer

**append 必须接住返回值**：

```go
s := []int{1, 2, 3}
append(s, 4)    // 错：可能丢掉新底层数组
s = append(s, 4)
```

子切片共享数组：`b := a[0:2]; b[0] = 9` 会改 `a`。要独立拷贝用 `slices.Clone` 或 `copy`。

**`:=` 遮蔽**：

```go
err := doA()
if err != nil { return err }
if err := doB(); err != nil { // 这是新的 err，只在 if 内
    return err
}
// 外面的 err 仍是 doA 的结果
```

想更新已有变量用 `=`，或 `err = doB()`。`go vet` 能抓一部分。

**range 是副本**：

```go
for _, v := range items {
    v.X = 1 // 改不到 items 里
}
for i := range items {
    items[i].X = 1
}
```

指针切片才适合「range 出来还能改对象」。Go 1.22 前闭包捕获循环变量几乎总是最后一轮的值，用形参传入。

**defer LIFO**，参数当时求值：

```go
defer fmt.Println("First")
defer fmt.Println("Second")
// 输出 Second 然后 First

func f() {
    n := 1
    defer fmt.Println(n) // 打印 1，不是 2
    n = 2
}
```

`defer mu.Unlock()` 紧跟 `Lock()`。循环里 `defer` 会堆到函数结束才跑，文件要在循环内手动 `Close`，或包一层函数。

## 三、类型、JSON、包

**JSON 只导出大写字段**：

```go
type User struct {
    Name string `json:"name"`
    age  int    // 不会出现在 JSON 里
}
```

习惯 JS 全公开的人最容易踩。私有字段想序列化只能自己写 `MarshalJSON`，一般不要。

**nil 接口 ≠ nil 指针**：

```go
var p *MyError = nil
var err error = p
fmt.Println(err == nil) // false：接口里还有类型 *MyError
```

返回 error 时写 `return nil`，不要 `return 某个 nil 指针`。自定义 error 用值还是指针要在整个包内一致。

**未使用变量 / import 是编译错误**，不是 warning。占位用 `_`。

**循环导入**：A import B、B import A，直接失败。抽 `interfaces`/`models` 第三包，或让一方只依赖接口。

**go.mod 和源码不一致**：`go mod tidy`。不要手改 `go.sum`。

**变量零值可用**：`var sb strings.Builder`、`var mu sync.Mutex` 不用 new。`map`、切片、指针、channel 的零值是 `nil`，写 map 前要 `make`。

## 四、惯用法（写得像 Go）

- **格式化无争论**：提交前 `gofmt`。命名：包名小写短词；导出类型 `CamelCase`；缩写全大写 `URL`、`ID`。
- **错误**：见到 `error` 就处理或往上包，不吞。
- **接口小**：在使用方定义接口，而不是在实现方预先摊大接口。
- **组合优于继承**：嵌套结构体，不造类层次。
- **`make` vs `new`**：`make` 给 slice/map/chan；`new(T)` 得到 `*T` 且指向零值，多数时候 `x := T{}` / `&T{}` 更清楚。
- **少反射、少 `any`**：热路径用具体类型。对象池用 `sync.Pool` 减 GC，先 pprof 再上。
- **控制 goroutine 数量**：来一个请求可以一个 goroutine；批处理用 worker pool，不要 `for` 里无上限 `go`。
- **包职责单一**：`main` 只组装；业务放 `internal/`。
- **现代特性点到为止**：泛型用于容器/工具函数；`embed` 把静态文件打进二进制；模块用 `go.mod`，不要 GOPATH 模式。

性能顺序：正确 → 测量（pprof）→ 改分配和算法。过早用接口、反射、超细粒度锁通常更慢。

> **面试要点**：从 JS 转过来最高频的三连：JSON 字段大小写、`:=` 造新变量、`err` 接口装了 nil 指针。这三道能讲清楚，陷阱篇就算过关。
