# JS 转 Go：错误处理

> **本页关键词**：error 是值、`if err != nil`、`%w`、`errors.Is`、`errors.As`、哨兵错误、早期返回、panic/recover

---

## 一、哲学：错误是值

JS 用 `throw` / `try/catch`，错误会跳栈。Go 把失败当成普通返回值，调用方必须看见、必须处理。没有隐藏的 catch 路径。

```go
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("除零")
    }
    return a / b, nil
}

result, err := divide(10, 0)
if err != nil {
    fmt.Println(err)
    return
}
fmt.Println(result)
```

| | JavaScript | Go |
| --- | --- | --- |
| 机制 | 异常 | `error` 值 |
| 传播 | 自动上抛 | 手动 `return err` |
| 控制流 | 可被 catch 打断 | 直线往下，失败就提前 return |
| 异步 | `try/catch` + Promise rejection | 同一套 `error`，经 channel 传回即可 |

> **面试要点**：优点是错误路径看得见；缺点是啰嗦。Go 团队认为「显式」比「少写几行」重要。不要用 panic 模拟 throw。

## 二、`error` 接口

```go
type error interface {
    Error() string
}
```

任何带 `Error() string` 的类型都是 error。自定义错误带字段：

```go
type ValidationError struct {
    Field, Message string
}

func (e ValidationError) Error() string {
    return e.Field + ": " + e.Message
}

func validate(name string) error {
    if name == "" {
        return ValidationError{Field: "name", Message: "必填"}
    }
    return nil
}
```

哨兵错误：包级变量，表示固定语义（对照 `ENOENT`）：

```go
var ErrNotFound = errors.New("not found")

func Find(id int) error {
    if id < 0 {
        return ErrNotFound
    }
    return nil
}
```

比较包装过的错误要用 `errors.Is`，不要 `err == ErrNotFound`。

## 三、包装与判定

Go 1.13+ 用 `%w` 包一层上下文，同时保留原错误：

```go
data, err := os.ReadFile(path)
if err != nil {
    return fmt.Errorf("读配置 %s: %w", path, err)
}
```

| API | 用途 | JS 类比 |
| --- | --- | --- |
| `fmt.Errorf("...: %w", err)` | 包一层 | `Error` 的 `cause` |
| `errors.Unwrap(err)` | 剥一层 | — |
| `errors.Is(err, ErrNotFound)` | 沿链找哨兵 | `error === CODE` |
| `errors.As(err, &valErr)` | 沿链找具体类型 | `instanceof` |

```go
if errors.Is(err, ErrNotFound) {
    // 404
}

var vErr ValidationError
if errors.As(err, &vErr) {
    fmt.Println(vErr.Field)
}
```

`%v` 只字符串化，**不会**加入错误链；要能 `Is`/`As` 必须用 `%w`。

## 四、写法习惯

**早期返回**，不要嵌套 `if err == nil { ... }`：

```go
func loadUser(id string) (*User, error) {
    u, err := repo.Get(id)
    if err != nil {
        return nil, fmt.Errorf("get user: %w", err)
    }
    if err := u.Validate(); err != nil {
        return nil, fmt.Errorf("validate: %w", err)
    }
    return u, nil
}
```

不要 `_ = do()` 丢掉 error。唯一能忽略的是你确定无意义的关闭错误，也要写清楚原因。

多个校验错误可以聚合成一个类型：

```go
type ValidationErrors struct{ Msgs []string }

func (e ValidationErrors) Error() string {
    return strings.Join(e.Msgs, "; ")
}
```

日志里打 `%v` 或 `%+v`（部分库），返回给调用方时继续包，不要只 `log` 然后返回 `nil`。

## 五、panic 与 recover

`panic` 类似未捕获异常：栈展开，一路执行 `defer`。`recover` **只能写在 defer 里**，把 panic 变成值。

适用：真正不可继续的程序错误（数组越界、配置在启动时就坏了）。业务失败用 `error`。

```go
func mustCompile(expr string) *regexp.Regexp {
    re, err := regexp.Compile(expr)
    if err != nil {
        panic(err) // 启动期常量，编不过就别跑
    }
    return re
}

func Guard(h http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        defer func() {
            if rec := recover(); rec != nil {
                http.Error(w, "internal", 500)
            }
        }()
        h.ServeHTTP(w, r)
    })
}
```

goroutine 里的 panic 不会被其他 goroutine 的 recover 接到。HTTP 中间件要自己套一层，否则一个 handler panic 就能干掉整个进程。

## 六、并发里的 error

`go f()` 的返回值会被丢掉。几种做法：

- 错误 channel：`errCh <- err`（注意缓冲，避免阻塞）
- `errgroup.Group`（`golang.org/x/sync/errgroup`）：第一个错误取消其余，类似 `Promise.all` 失败短路
- 收集：每个结果 `{val, err}` 放进 channel，类似 `Promise.allSettled`

```go
g, ctx := errgroup.WithContext(ctx)
g.Go(func() error { return jobA(ctx) })
g.Go(func() error { return jobB(ctx) })
if err := g.Wait(); err != nil {
    return err
}
```

> **面试要点**：能画出 `New` → `%w` 包装 → `Is`/`As` 判定这条链，再说「panic 只给不可恢复 + 中间件 recover」，错误处理题就闭环了。
